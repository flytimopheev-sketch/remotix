# Руководство пользователя Remotix

Как пользоваться Remotix: от первого запуска до импорта старых подключений,
групп, тегов и метрик. Предполагается РЕД ОС 7/8 (или любой дистрибутив
с GTK4 ≥ 4.4); синтаксис путей — Linux.

## Первый запуск

1. При первом запуске Remotix предложит придумать **мастер-пароль** — это
   ключ ко всем сохранённым паролям. Он нигде не хранится, восстановить
   его нельзя: запомните или положите в менеджер паролей.
2. Профили, история и настройки лежат в `~/.local/share/remotix/remotix.db`
   (учётные данные — только в зашифрованном виде).

## Профили подключений

**Новый профиль** (`Ctrl+N`): имя, протокол (SSH/RDP), адрес, порт,
логин/пароль. Дополнительно:

- **SSH** — путь к ключу, режим двухступенчатого входа (войти под админом
  и переключиться на root через `su -` с вводом root-пароля), бастион
  (SSH jump host);
- **RDP** — разрешение экрана, домен, NLA; режим RC4 включается только
  вручную (см. «RDP и старые серверы»);
- любой профиль — MAC-адрес для Wake-on-LAN.

Рядом с полями пароля и root-пароля есть кнопка **«Сгенерировать»**:
20 символов, среди них обязательно есть строчная и заглавная буква, цифра
и символ. Источник случайности — `OsRng` (криптостойкий ГПСЧ ОС), готовый
пароль сразу подставляется в поле.

> Протокол VNC в редакторе пока является заготовкой: подключение по нему
> не выполняется, при попытке открыть сессию программа сообщает о разработке.

Подключение — двойной щелчок по профилю. Правый клик: изменить,
дублировать, удалить.

## Бастион (SSH jump host)

Чтобы подключаться к внутреннему узлу через промежуточный сервер, создайте
и сохраните профиль самого бастиона (SSH), затем в свойствах целевого
профиля выберите его в поле **«Бастион (SSH)»**. Бастион должен быть уже
сохранён — список берётся из профилей.

- Работает для SSH-терминала и SFTP: TCP-соединение до целевого узла
  открывается каналом `direct-tcpip` на бастионе.
- Ключи хоста проверяются у обоих серверов: сначала у бастиона, затем у
  целевого узла (по его собственному адресу и порту).
- Поддерживается один уровень: профиль, который сам ходит через бастион,
  в списке не появляется.
- Если бастион удалить, ссылка снимается, и цель подключается напрямую.

## Группы и теги

- **Группы** — дерево в боковой панели. Правый клик по группе: создать
  подгруппу, переименовать, удалить (профили при удалении группы не
  пропадают — поднимаются на уровень выше). Профиль переносится через
  правый клик → «Переместить в группу…».
- **Теги** — свободные слова (`прод`, `тест`…). Над списком подключений
  фильтр по тегу; у строки профиля теги подписаны рядом с адресом.
- Свёрнутое состояние групп сохраняется между запусками.

## Поиск и быстрое подключение

- `Ctrl+F` — поиск по профилям (имя, хост, логин).
- Поле быстрого подключения принимает `user@host` — откроется SSH-сессия
  без создания профиля.

## Метрики хоста (SSH)

На SSH-вкладке сверху панель: CPU, память, приём/отдача (КБ/с), load
average, заполненность корневой ФС. Опрос раз в 5 секунд, без установки
чего-либо на сервер — читаются `/proc/stat`, `/proc/meminfo`,
`/proc/net/dev`, `/proc/loadavg` и `df -P /`. После трёх неудачных опросов
панель гаснет. Включается/выключается в Параметры → Терминал →
«Метрики хоста».

## Запись сессий (SSH)

Переключатель в Параметры → Терминал → «Запись сессий» (по умолчанию
выключена — сознательное решение в пользу приватности, учётные записи
root и так доверяются терминалу). Пока включена, каждая SSH-сессия
записывается в два файла в `~/.local/share/remotix/recordings/`:

- `session-<хост>-<время>.log` — typescript, сырой вывод сессии;
- `session-<хост>-<время>.timing` — паузы и размеры порций.

Формат — util-linux `script`(1), поэтому воспроизведение штатное:

```bash
scriptreplay -T session-host-20261029-090000-123.timing \
             -O session-host-20261029-090000-123.log
```

Работает и `scriptreplay --summary` (длительность и код закрытия сессии).
Ввод (пароли) в файлы не попадает — записывается только вывод; то же,
что видел экран. При превышении 256 МБ запись останавливается, сессия
продолжает работать. Каталог можно перенести переменной
`REMOTIX_RECORDINGS_DIR`.

## Автоответы (expect-правила)

Параметры → Автоответы. Правило: шаблон вывода терминала → строка,
которая отправится в канал при совпадении (Enter добавляется
автоматически). Примеры:

- шаблон `*assword*:` → ответ с паролем — автоматический вход по паролю;
- шаблон `[yes/no]*:` → ответ `yes` — подтверждение отпечатка или вопрос.

В шаблоне `*` — любая последовательность символов, `?` — ровно один
символ, остальное — литералы (регулярные выражения не используются).
Флаг «Один раз» срабатывает первое совпадение за сессию; без него
правило срабатывает на каждый промпт. Ответы хранятся в БД зашифрованно
(как пароли), в списке не отображаются — открыть можно значком глаза
в поле изменения.

Ограничения по безопасности: правило глобальное — применяется ко всем
SSH-сессиям. Не кладите в ответ пароль, который не должен уйти на
другой хост: если промпт появится на неожиданном сервере, ответ уйдёт
туда. Для точечных сценариев держите правило выключенным и включайте
перед нужным подключением.

## Сниппеты команд

Параметры → Сниппеты. Сниппет — имя и команда, которую нужно часто
запускать на сервере (например, `df -h` или `systemctl status nginx`).
В открытой SSH-сессии над терминалом появляется меню **«Сниппеты»**:
выбор пункта отправляет команду в канал и добавляет Enter, как если бы
она была набрана вручную.

Команды хранятся в БД зашифрованными (тем же ключом, что и пароли), но
это не менеджер секретов: текст команды виден в списке параметров, а
сама команда попадает в историю оболочки на сервере. Не сохраняйте в
сниппетах пароли и токены.

## Терминал

- Если установлен `vte291-gtk4` — полноценная эмуляция (цвета, `vim`,
  `htop`); если нет — упрощённый терминал с тем же вводом/выводом.
- Копирование/вставка — `Ctrl+Shift+C` / `Ctrl+Shift+V`.
- Масштаб шрифта — `Ctrl+`+` / `Ctrl+`-` (восстановится при следующем
  запуске? — нет, масштаб внутри сессии; постоянный размер — в Параметрах).
- Мигание курсора, шрифт, размер и цветовая схема — Параметры → Терминал.
- Палитры терминала: **Тёмная** (по умолчанию), **Светлая**,
  **Solarized Dark**, **Dracula**, **Nord**, **Gruvbox** и **Как в системе**
  (тёмная или светлая по теме рабочего окружения). Схема применяется и к
  VTE, и к упрощённому терминалу, включая 16 цветов ANSI.
- При запуске Remotix заново открывает SSH-терминалы, SFTP- и RDP-вкладки,
  которые были открыты при выходе (Параметры → Терминал → «Восстанавливать
  вкладки»). Профили, удалённые за это время, пропускаются.

## Импорт подключений

Параметры → Профили. Источники и что с ними происходит:

| Источник | Что учитывается | Что пропускается |
| --- | --- | --- |
| `~/.ssh/config` | `Host`, `HostName`, `User`, `Port`, `IdentityFile`, `Include` (вложенность ≤ 8, циклы отслеживаются) | шаблоны `*`/`?`/`!`, `Match`, `ProxyJump`/`ProxyCommand` — с причиной |
| Remmina (`*.remmina`) | SSH/RDP/VNC-подключения | туннели и шлюзы — с причиной |
| `.rdp` (mstsc) | адрес, порт, логин, домен, разрешение, NLA, буфер, перенаправления | пароли; «alternate shell» — предупреждение |
| CSV | колонки-алиасы RU/EN: `name/имя`, `host/адрес`, `port`, `protocol`, `user`, `tags`, `group`, `url` (`ssh://user@host:port`) | колонки паролей — с пометкой; разделитель (`;`/`,`/таб) распознаётся автоматически |
| JSON | экспорт Remotix | — |

Перед записью показывается предпросмотр: «импортируется N, пропущено M»
с причиной по каждой записи. Дубли (протокол + хост + порт + логин) не
задваиваются. **Пароли не импортируются и не экспортируются никогда.**

## Проверка ключа SSH-хоста

Первое подключение к серверу показывает тип ключа и SHA256-отпечаток.
Ключ принимается только явно и дописывается в `~/.ssh/known_hosts`
(переопределяется переменной `REMOTIX_KNOWN_HOSTS`). Если отпечаток
известного сервера изменился — подключение заблокировано: сначала
убедитесь, что сервер действительно менял ключ, затем исправьте запись
вручную.

## Проверка доступности и Wake-on-LAN

Перед SSH/RDP/SFTP выполняется TCP-проба (3 с). Порт не отвечает →
предложение разбудить машину (если задан MAC-адрес), подключиться
всё равно или отменить. Пробуждение: magic packet UDP на порты 9 и 7,
затем ожидание до 10 минут (прерывается кнопкой «Отмена»). В BIOS/UEFI
и на сетевом адаптере должна быть включена поддержка Wake-on-LAN.

## SFTP

Вкладка SFTP — две панели (локальный каталог слева, серверный справа):

| Клавиша | Действие |
| --- | --- |
| `↑` / `↓` / `Enter` / `Backspace` | навигация |
| `Tab` | переключить панель |
| `F5` | копировать в другую панель |
| `F6` | переименовать |
| `F7` | создать каталог |
| `F8` / `Delete` | удалить |
| `F10` | закрыть вкладку |
| `Ctrl+R` | обновить |
| `Ctrl+C` / `Ctrl+V` | копировать/вставить объекты |

## RDP и старые серверы

По умолчанию — TLS и NLA (CredSSP). Если сервер умеет только Standard
RDP Security (RC4) — старые Windows, xrdp с `security_layer=rdp` —
в свойствах профиля включите «Разрешить незащищённый RDP (RC4)» и
подтвердите предупреждение. Режим не проверяет подлинность сервера,
используйте только для доверенных хостов. Лучше включить на сервере
TLS (xrdp: `security_layer=negotiate` + сертификат, см. README).

## Журнал подключений

Кнопка в строке состояния: все подключения с временем и результатом,
экспорт в CSV (`~/remotix-history.csv`).

Над списком показывается сводка: сколько всего подключений, сколько
успешных и с ошибкой, период журнала и топ-5 профилей по числу
подключений. Сводка пересчитывается кнопкой «Обновить». Длительность
сессий не показывается: журнал фиксирует момент подключения, а не время
работы (SSH-сессия может оставаться открытой часами).

## Переменные окружения

| Переменная | Значение |
| --- | --- |
| `REMOTIX_MASTER_PASSWORD` | открыть хранилище без диалога (для скриптов/smoke-тестов) |
| `REMOTIX_KNOWN_HOSTS` | путь к known_hosts вместо `~/.ssh/known_hosts` |
| `REMOTIX_RECORDINGS_DIR` | каталог записей сессий (по умолчанию `~/.local/share/remotix/recordings`) |
| `XDG_DATA_HOME` | база данных ищется в `$XDG_DATA_HOME/remotix` |

## Частые проблемы

| Симптом | Решение |
| --- | --- |
| Не открывается хранилище | мастер-пароль неверный; восстановления нет — базу можно только начать заново (профили придётся ввести заново или импортировать) |
| Терминал без цветов | установите `vte291-gtk4` |
| «Хост, возможно, выключен» | проверьте питание/сеть; используйте Wake-on-LAN |
| Изменился отпечаток SSH-хоста | не слепо удаляйте запись known_hosts — проверьте сервер |
| Панель метрик пропала | три неудачных опроса подряд (нет `/proc`-доступа?) — она скрывается автоматически |
